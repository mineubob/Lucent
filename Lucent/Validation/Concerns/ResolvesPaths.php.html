7/**
8 * Shared helpers for resolving dotted field paths.
9 *
10 * A dotted path (`user.name`, `items.0`) addresses a value inside a nested
11 * array. This trait provides the common operations — splitting a path into
12 * segments and reading a value by path — used by {@see \Lucent\Validation\Result},
13 * {@see \Lucent\Validation\FieldContext}, and the shape combinators.
14 *
15 * **Dotted keys are not supported.** The `.` character is always treated as a
16 * path separator, so a field key that itself contains a dot (e.g. a literal
17 * `user.name` key) is ambiguous and cannot be addressed. Field names should
18 * avoid dots. The cached segments in {@see \Lucent\Validation\FieldContext}
19 * are kept consistent with the dotted-path string: a leaf name containing a
20 * dot is split into multiple segments, matching how the string is parsed.
21 */

28     * for a literal dot in a key.
