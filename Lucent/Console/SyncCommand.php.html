18/**
19 * The `sync` command — diff the discovered models' desired schema against
20 * the live database and apply it.
21 *
22 * The whole plan → display → apply flow runs under the `radiant:schema`
23 * lock (plan() and apply() take no lock themselves), so the shown plan is
24 * guaranteed to be exactly what gets applied.
25 *
26 * Output is echoed progressively (visible live in a terminal); in captured
27 * mode (tests) the ob_start wrapper in executeConsoleCommand() still
28 * collects it, so the return value is always ''.
29 *
30 * Filters: `--filter` / `--exclude-filter` are matched against
31 * fully-qualified class names; exclude wins. A pattern that is not a valid
32 * regular expression is treated as a literal substring match. Excluded
33 * models' tables are resolved best-effort into a protected list, passed to
34 * the differ — a protected table is never dropped and never offered as a
35 * rename target (an excluded model must not look orphaned to the differ).
36 *
37 * Transactional apply: on by default when the dialect supports transactional
38 * DDL (SQLite, PostgreSQL); MySQL DDL auto-commits, so a warning is shown
39 * and the apply runs non-transactionally. Opt out with --no-transactional.
40 *
41 * Additive-only mode: --no-drop-tables suppresses DropTable changes for
42 * tables no model declares (orphans, other tools' tables) — the plan can
43 * only create and alter. Column-level drops are NOT suppressed: a live
44 * column missing from the model still diffs as a destructive DropColumn,
45 * covered by the destructive confirm gate.
46 *
47 * Rename suggestions: when the differ flags a create/drop pair as a
48 * POSSIBLE RENAME, the command prompts — confirming declares the rename on
49 * the blueprint (renamedFrom) and re-plans, so the differ emits the real
50 * RenameTable change together with any column shape drift in one plan.
51 */

268     * blueprint — the decision, not a guess.
269     *
270     * When the user confirms, the desired blueprint for the new table gets
271     * a renamedFrom declaration; the caller re-plans so the differ verifies
272     * the declaration and emits the real RenameTable change. Each old table
273     * can only be claimed by one rename (the differ pairs every create with
274     * its best-overlap drop, so multiple creates can claim the same drop —
275     * first claim wins).

278     * flagged pair is kept as-is (the plan shows the POSSIBLE RENAME
279     * annotation and the destructive gate handles it) — never block on
280     * stdin we cannot read.

293                $pairs[$change->table] = $change->renameOf;
294            }
295        }
296
297        if ($pairs === []) {
298            return false;
299        }
300
301        // No TTY and no --force: keep the flagged pair as-is.
302        if (!$force && !self::isInteractive()) {
303            return false;

306        $declared = false;
